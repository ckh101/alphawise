# 智能投研Agent 开发部署文档

版本：0.1.0 | 更新日期：2026-06

---

## 架构总览

本项目是 Electron 桌面客户端，由**三层进程**组成：

```
┌─────────────────────────────────────────────────────────────┐
│  Electron 主进程 (main.js)                                    │
│  ├─ 渲染进程 (src/renderer/)  ← UI（vanilla HTML/CSS/JS）     │
│  └─ spawn → Node.js 后端 (server/index.js, Fastify, :9998)   │
│              └─ spawn → Python Worker (worker_main.py, :9999)│
│                            ├─ Agent 编排 (ReAct / Claude SDK) │
│                            ├─ Skills (TDX / GLM / 搜索 / 回测)│
│                            ├─ 飞书通道 (WebSocket)            │
│                            └─ 定时任务调度 (APScheduler)      │
└─────────────────────────────────────────────────────────────┘
```

- **渲染进程** → Axios → Node.js 后端（9998）→ `pythonWorker.request()` → Python Worker（9999）
- Python Worker 是**持久化进程**（`detached:true`），Electron 关闭后仍存活，重开时复用
- 端口：`9998`（Node Fastify）、`9999`（Python Worker JSON-RPC）

> ⚠️ 注意：早期版本的文档把"Python FastAPI 后端 `main.py`"当作主后端，**已过时**。当前 Node.js 后端才是 API 入口；Python 端的 `harness/api/main.py`（FastAPI :8000）在桌面客户端里**不启动**，仅作历史代码保留。

## 1. 开发环境搭建

### 前置条件

- Python 3.10+（建议 3.11/3.12；本机 venv 已可用的 3.14 也可）
- Node.js 18+
- Git
- Windows / macOS

### 1.1 克隆项目

```bash
git clone <repo-url> alphawise
cd alphawise
```

### 1.2 后端环境（Python Worker）

```bash
cd backend

# 创建虚拟环境
python -m venv .venv

# 激活（Windows）
.venv\Scripts\activate
# 激活（macOS/Linux）
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt

# TA-Lib（Windows）：从 https://github.com/cgohlke/talib-build/releases
# 下载对应版本 wheel，然后
pip install TA_Lib-0.4.28-cp3xx-cp3xx-win_amd64.whl
# TA-Lib（macOS）：brew install ta-lib && pip install ta-lib

# Playwright 浏览器搜索用的 Chromium（首次需要）
python -m playwright install chromium
```

环境变量配置（可选，主要配置走 UI 设置页写入 DB）：

```bash
cp .env.example .env
# 编辑 .env 填入 GLM / Claude API Key 等
```

配置文件：`backend/resources/config/config.dev.yaml`（通过 `HARNESS_ENV=dev` 加载）。

### 1.3 前端环境（Electron + Node 后端）

```bash
cd frontend
npm install
```

### 1.4 启动开发环境

**只需一条命令**（推荐）：

```bash
cd frontend
npm run dev
```

这会启动 Electron，Electron 主进程 (`main.js`) 自动：
1. spawn Node.js 后端（监听 `127.0.0.1:9998`）
2. Node 后端的 `pythonWorker.js` spawn Python Worker（监听 `127.0.0.1:9999`），或复用已存活的持久化 Worker
3. 等 Worker `/ready` 返回 ok（Agent 初始化完成）后加载 UI

> 历史 `scripts/dev.bat` / `dev.sh` 仍存在，但日常开发用 `npm run dev` 即可，**不需要开多个终端分别启动后端**。

### 1.5 单独启动各层（调试用）

通常不需要。仅在定位某层问题时单独跑：

```bash
# 仅 Node.js 后端（:9998）
cd frontend
node server/index.js

# 仅 Python Worker（:9999）
cd backend
.venv\Scripts\python.exe worker_main.py   # Windows
.venv/bin/python worker_main.py           # macOS/Linux
```

## 2. 首次配置教程

首次跑通项目需完成三件事：初始化数据库、配置 AI（GLM/Claude）、接入飞书机器人（可选）。

### 2.1 初始化数据库（自动，无需手动）

数据库**无需手动建表**。Worker 启动时 `harness/core/database.py` 的 `init_db()` 会自动 `create_all` 建表。

- 首次 `npm run dev` 启动时，Python Worker 初始化阶段自动建库建表
- 数据库路径：优先取 `config.dev.yaml` 的 `storage.database_path`，默认 `./data/harness.db`
- 表：`stocks`（全量股票，每日 03:00 同步）、`watchlist`（自选）、`settings`（配置）、`scheduler_tasks`（定时任务）、`agent_sessions`、`llm_calls`

首次启动后验证：

```bash
sqlite3 backend/data/harness.db ".tables"
# 应看到: agent_sessions  llm_calls  scheduler_tasks  settings  stocks  watchlist
```

> 若要重置：关闭 Worker → 删除 `backend/data/harness.db*`（含 `-wal`/`-shm`）→ 重启自动重建（**会清空所有配置和数据**）。

### 2.2 环境变量与 API Key 配置

> ⚠️ **重要**：项目**不读取 `.env` 文件**（没有 `load_dotenv`）。`backend/.env.example` 是历史遗留文件，**内容已过时且不生效**，不要依赖它。环境变量有两条生效路径：config 文件、或 UI 设置页。

#### 路径 A：配置文件（默认值，适合开发）

`backend/resources/config/config.dev.yaml` 是主配置源（`HARNESS_ENV=dev` 时加载）。关键字段：

```yaml
glm:
  api_key: "<你的 GLM API Key>"
  base_url: "https://open.bigmodel.cn/api/paas/v4/"
  model: "glm-4.7"

claude:                  # Claude Agent SDK 配置
  ...
```

- **GLM API Key 获取**：登录 [智谱开放平台](https://open.bigmodel.cn/) → 控制台 → API Keys → 创建/复制
- `model` 当前主力用 `glm-4.7`（或 `glm-4-flash` 等更便宜的）

#### 路径 B：UI 设置页（推荐，运行时可改）

启动应用 → 设置页 → "环境变量"分组 → 添加变量 → 保存 → **重启 Worker 生效**。

注入链：UI → `settings` 表 → Node 端 `getEnvVars()` → `pythonWorker spawn` 时作为环境变量注入子进程（`pythonWorker.js:_getCustomEnv`）。

例如要加一个 `IWENCAI_API_KEY`：设置页添加 → 重启 Worker → Worker 进程的 `os.environ` 即有该值。

#### 路径 C：多厂商 LLM Provider（UI 管理）

设置页 → "大模型"分组 → "添加厂商"。每个 Provider 含 `name / api_key / base_url / model / timeout`，可配多个厂商并切换"当前使用"。存于 `settings` 表的 `llm_providers` / `llm_active_provider`。Claude 走此路径配置（通过 `get_sdk_config()` 注入 SDK，不再写 `os.environ`）。

### 2.3 飞书机器人接入（可选）

飞书机器人用于：①接收用户 @机器人的消息触发对话分析；②定时任务结果主动推送。

> **澄清**：定时任务**主动推送**走飞书 HTTP REST API（`im.v1.message.create`），只需 `app_id` + `app_secret`，**不需要 WebSocket 通道在线**。WebSocket 通道仅用于**接收**用户消息。

#### 第 1 步：创建飞书应用

1. 打开 [飞书开放平台](https://open.feishu.cn/app) → 创建企业自建应用
2. 记下 **App ID** 和 **App Secret**（`cli_xxx` 开头）
3. 在「事件与回调」→ 选择 **长连接（WebSocket）模式**（本项目用 `lark-oapi` 的 `WsClient`，不走 HTTP 回调）
4. 在「事件订阅」添加事件：**接收消息 v2.0**（`im.message.receive_v1`）
5. 在「权限管理」开通：
   - `im:message`（发送消息）
   - `im:message:send_as_bot`（以机器人身份发消息）
   - `im:chat`（群信息，群聊场景需要）
6. 在「机器人」菜单启用机器人，配置机器人名称（**必须与设置页通道名一致**，用于多机器人去重）
7. 发布版本 → 等待企业管理员审批通过

#### 第 2 步：获取用户 open_id（推送目标）

定时任务推送给指定用户，需要该用户的 `open_id`（注意：**open_id 是应用隔离的**，同一用户在不同应用里 open_id 不同）。

获取方式：
- 在飞书开放平台「开发者后台」→ 你的应用 → 「API 调试台」→ 调 `contact/v3/users/batch_get_id`（用手机号/邮箱换 open_id）
- 或机器人收到该用户消息后，从事件数据的 `sender.sender_id.open_id` 取

> ⚠️ **open_id 跨应用会报错**：用 A 应用的凭证给 B 应用的 open_id 发消息，飞书返回 `99992361 open_id cross app`。本项目每个定时任务绑定一个飞书通道，推送时自动用该通道（同应用）的凭证，避免此问题。

#### 第 3 步：在应用内配置通道

设置页 → "飞书通道"分组 → "添加通道"，填入：

| 字段 | 说明 |
|------|------|
| 通道名称 | 必须与飞书后台的机器人名称**完全一致**（多机器人去重依赖） |
| App ID | `cli_xxx` |
| App Secret | 应用密钥 |
| Verification Token | 可空（长连接模式不需要） |
| Encrypt Key | 可空（长连接模式不需要） |
| 推送目标 receive_id | 用户的 `ou_xxx`（open_id） |
| 推送目标类型 | `open_id`（私聊）或 `chat_id`（群） |

保存后通道自动重载启动。多通道场景：每个飞书应用一个通道，本项目支持同时连接多个。

#### 第 4 步：验证

1. 设置页应显示通道"已连接"
2. 命令行验证：

```bash
curl -X POST http://127.0.0.1:9999/rpc \
  -H "Content-Type: application/json" \
  -d '{"method":"feishu.status","params":{}}'
# 期望: channels_running 列出你的通道 id
```

3. 在飞书里 @机器人发条消息，看 `logs/worker.log` 是否收到事件
4. 手动触发一个定时任务，看是否收到推送（`grep "send_feishu_message" logs/worker.log`）

#### 常见问题

| 现象 | 原因 / 解决 |
|------|------------|
| 通道一直"未连接" | App ID/Secret 错；或事件未配置 `im.message.receive_v1`；或应用未发布 |
| @机器人无响应 | 通道名与飞书机器人名不一致（去重逻辑跳过了）；看 worker.log 的 `not @me, skip` |
| 推送报 `open_id cross app` | 任务的 receive_id 与通道应用不同源；确认 receive_id 取自该应用 |
| 推送报权限错误 | 飞书后台未开通 `im:message:send_as_bot` 权限 |

## 4. 日常开发与调试

### 3.1 改动后如何生效

| 改动位置 | 生效方式 |
|---------|---------|
| 渲染进程（`src/renderer/*.html/js/css`） | 刷新窗口（`Ctrl+R`）。**改了 JS/CSS 必须 bump `index.html` 里的 `?v=N`**，否则 Electron 缓存不更新 |
| Node.js 后端（`frontend/server/**`） | **重启 Electron**（关掉重开），或单独重启 Node 后端 |
| Python Worker（`backend/**`） | 设置页点"重启 Worker 进程"，或重启 Electron（Worker 持久化，需手动 restart） |
| 配置（`config.dev.yaml`） | 重启 Worker |
| 环境变量（设置页注入） | 重启 Worker 生效 |

### 3.2 日志查看

所有日志在 `logs/`：

| 文件 | 内容 |
|------|------|
| `electron.log` | Electron 主进程 + 后端子进程 stdout/stderr（最全） |
| `server.log` | Node.js Fastify 请求日志（pino JSON） |
| `worker.log` | ★ Python Worker 日志（Agent / Skill / 飞书 / 定时任务，排查核心） |
| `errors.log` | ERROR 级别过滤 |
| `worker.pid` | 当前 Worker 进程 PID（运行时文件，勿提交） |

UI 内也有"查看日志"按钮（设置页 → 查看日志），对应 `log-viewer.js`。

实时跟踪 Worker 日志（排查定时任务/飞书推送首选）：

```bash
# Git Bash
tail -f logs/worker.log | grep -E "Task [0-9]+ status|send_feishu_message"
```

### 3.3 Worker 管理与重启

- **手动重启**：UI 设置页 → "重启 Worker 进程"。流程：清理僵尸 → kill 当前 → 等端口释放 → spawn 新进程 → 健康检查。
- **持久化**：Worker 用 `detached:true` 脱离 Node 父进程，Electron 关闭后仍存活；下次 Electron 启动时 `ensureReady()` 探测 `:9999/ready`，能复用就不重新 spawn。
- **僵尸清理**：`pythonWorker.js` 的 `_cleanupOrphanWorkers()` 通过 PID 文件 + 端口检测清理旧进程。
- **自动重启**：Worker 异常退出（exit code≠0）会 auto-restart，最多 5 次；若端口已被占用（说明有活 Worker）则跳过，避免重启风暴。

### 3.4 健康检查端点

```bash
# Worker 存活
curl http://127.0.0.1:9999/health      # → {"status":"ok"}

# Worker 就绪（Agent 初始化完成才 ok）
curl http://127.0.0.1:9999/ready       # → {"status":"ok"} 或 "initializing"

# 飞书通道状态
curl -X POST http://127.0.0.1:9999/rpc \
  -H "Content-Type: application/json" \
  -d '{"method":"feishu.status","params":{}}'

# Node 后端健康
curl http://127.0.0.1:9998/api/v1/health
```

### 3.5 端口占用排查

```bash
# Windows
netstat -ano | findstr ":9999"
netstat -ano | findstr ":9998"
# 杀残留 Worker
taskkill /F /PID <pid>
```

若 9999 被占但无响应（僵尸），删 `logs/worker.pid` 后重启 Electron，或手动 taskkill。

### 3.6 调试技巧

- **Electron DevTools**：开发模式下窗口聚焦时可用（`webSecurity:false`）。若没自动开，可在 `main.js` 的 `createWindow` 临时加 `mainWindow.webContents.openDevTools()`。
- **Python 断点**：在 `worker_main.py` 关键处 `import pdb; pdb.set_trace()`，但注意 Worker 是 detached 子进程，断点会挂起 Worker 导致 `/ready` 超时；更适合用日志（`logger.info`，loguru 已配置）。
- **数据库查看**：`sqlite3 backend/data/harness.db` 直接查 `scheduler_tasks`、`settings` 等。

## 5. 关键数据流（以一次对话为例）

```
用户输入 → /api/v1/agent/react/analyze
        → Node route → pythonWorker.request('agent.react.analyze')
        → ReactOrchestrator.execute():
            1. 提取股票代码（正则 + TDX 名称反查）
            2. LLM 意图识别 → domain / symbols / tool_plan
            3. 按 plan 执行工具（行情 → K线 → 技术 → 基本面 → 风险 → 搜索）
            4. 生成最终回复（report / chat / search_summary）
        → 返回渲染进程渲染
```

流式：`/api/v1/agent/react/analyze/stream` → `pythonWorker.requestStream()` → SSE。

定时任务：Python Worker 内 `APScheduler`（在 Worker 启动时由 Node 端通过 RPC 拉起调度器；任务从 DB 加载）→ 到点触发 `_execute_task` → 复用 `ReactOrchestrator` → `send_feishu_message` 主动推送（走飞书 HTTP REST API，不依赖 WebSocket 通道）。

### 7.1 版本号

同步修改三处：
- `backend/resources/config/config.dev.yaml` → `app.version`
- `backend/resources/config/config.prod.yaml` → `app.version`
- `frontend/package.json` → `version`

### 7.2 发布流程

1. 更新版本号
2. 测试通过 → `git tag v0.1.0`
3. 构建安装包
4. 上传更新服务器
5. 配置 `frontend/package.json` 的 `build.publish.url`

### 7.3 自动更新

```json
"publish": {
  "provider": "generic",
  "url": "https://your-server.com/updates"
}
```

服务器需提供 `latest.yml`（Windows）/ `latest-mac.yml`（macOS），electron-builder 构建时自动生成。

## 9. 注意事项

### TA-Lib
- **Windows**：用预编译 wheel（[cgohlke/talib-build](https://github.com/cgohlke/talib-build/releases)）
- **macOS**：`brew install ta-lib` → `pip install ta-lib`
- 打包时确保 TA-Lib 二进制包含在构建目录

### Playwright
- 首次浏览器搜索 Skill 自动下载 Chromium（~150MB）
- 或预装：`python -m playwright install chromium`

### 网络环境
- 通达信行情：需访问通达信服务器（配置了多个备用）
- GLM API：`open.bigmodel.cn`
- Claude API：`api.anthropic.com`
- 浏览器搜索：Bing CN（`cn.bing.com`）→ Bing 国际（`www.bing.com`）；DuckDuckGo/Google/搜狗在当前网络不可达

### 飞书通道
- 飞书 WebSocket 通道用于**接收**用户 @机器人消息（对话）；主动推送（定时任务结果）走 HTTP REST API，**不需要通道在线**
- 通道在 Worker 启动后由 Node 端 `_autoStartFeishuChannels` 自动拉起；也可在 UI 手动启停
- 多通道去重：`feishu_client.py` 的 `_on_message` 按 `msg.mentions[].name` 匹配 `channel_name`，@其他机器人的消息会跳过
